# `services/connection/` — абстракция транспорта

`GameContext` не знает, разговаривает ли он с реальным Socket.IO-сервером
или с локальной заглушкой. Он работает с интерфейсом `GameConnection`
(`types.ts`): `connect/disconnect/on/off/emit/getId`. Это единственная
точка, через которую в проект вообще попадают сетевые события.

## Файлы

- **`types.ts`** — интерфейс `GameConnection`.
- **`socketConnection.ts`** — реальная реализация поверх `socket.io-client`.
  `autoConnect: false` — сокет создаётся сразу, но не подключается, пока
  `GameContext` не зарегистрирует все `.on()`-подписки и явно не вызовет
  `.connect()`. Так исключается гонка "событие пришло раньше, чем на него
  подписались".
- **`mockConnection.ts`** — локальная симуляция сервера в одном классе:
  сама доигрывает "соперника" (авто-занимает второй слот в лобби через
  секунду, авто-подтверждает персонажа, авто-голосует за рестарт), чтобы
  можно было пройти весь FSM в одной вкладке без реального бэкенда. Держите
  её поведение синхронным с `server/src/gameRoom.js` при изменении контракта
  — иначе dev-режим без сервера начнёт врать.
- **`index.ts`** — `createConnection()`: если задан `VITE_WS_URL` (см.
  `client/.env.local`) — возвращает `socketConnection`, иначе — `mockConnection`.
  Индикатор в `DevPanel` ("SERWER"/"MOCK") показывает, какой из них активен.

## Как добавить новый `emit`

1. Убедиться, что сервер действительно слушает такое событие
   (`server/server.js` → `socket.on(...)`).
2. Вызывать `emit("имя:события", payload)` из компонента через `useGameEmit()`
   — отдельная функция-обёртка не нужна, `GameConnection.emit` уже типизирован
   достаточно широко.
3. Если нужно поведение и в dev-режиме без сервера — добавить `case` в
   `mockConnection.emit()`.

## Как добавить новое входящее событие

См. `client/src/game/README.md` — раздел "Как добавить новое серверное
событие". Коротко: дописать в `EVENT_TYPES` (`GameContext.tsx`), в
`ServerAction` (`game/types.ts`), добавить `case` в `gameReducer.ts`.
