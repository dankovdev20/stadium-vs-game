# `feature/` — конвенция самодостаточных фич

Каждая папка внутри `feature/` — законченный кусок логики+UI, который
можно понять и переиспользовать не зная остального приложения. Структура
внутри всегда одна и та же:

```
feature/<имя>/
  model/   — состояние, хуки, чистые данные (никакого JSX)
  ui/      — компоненты (могут использовать хуки из model/)
```

`feature/` отличается от `screens/`: экран — это "что показать при фазе X"
(привязан к `App.tsx`/FSM), фича — самостоятельный модуль, которым экран
пользуется. Один экран может использовать одну фичу (`CustomizationScreen`
→ `character-builder`) или фича может не иметь экрана вовсе и жить прямо в
`App.tsx` (`play-again` — это тост поверх текущего экрана, не отдельная фаза).

## Примеры

- **`play-again/`** — модалка "Играть снова" после `GAME_OVER`.
  `ui/PlayAgainModal.tsx` — самодостаточный компонент: сам читает
  `useGameState()`/`useGameEmit()`, никаких пропсов с данными не принимает.
  `model/usePlayAgainModal.tsx` — тонкая обёртка над `react-toastify`
  (открыть/закрыть тост), больше ничего не делает специально, потому что
  сам компонент уже самодостаточен.
- **`character-builder/`** — конструктор персонажа на экране CUSTOMIZATION.
  `model/options.ts` — статичные данные вариантов (голова/торс/ноги).
  `model/useCharacterBuilder.ts` — локальный стейт выбора (ничего не знает
  о сокетах). `ui/CharacterBuilder.tsx` принимает `onSubmit(character)` —
  экран-обёртка (`CustomizationScreen`) сам решает, что делать с выбором
  (эмитить `character:submit`).

## Когда заводить новую фичу, а не компонент в `screens/`

Если кусок UI+логики имеет собственное состояние и может быть отрендерен
больше чем в одном месте (или вынесен в отдельный тест) — это фича.
Если это просто "вот что показать в этой фазе игры" — это экран
(`screens/`), и он может использовать одну или несколько фич внутри себя.
