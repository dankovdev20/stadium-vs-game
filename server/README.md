# Stadium VS — Backend Engine

Серверная часть 1v1-пенальти для двух планшетов в локальной сети: комната
на всех подключившихся (без множественных комнат/лобби-листов — киоск на
выставке держит один матч единовременно), FSM-стейт-машина, расчёт исходов
по вероятностям из `gameRules.js`.

## Запуск

```bash
npm install
npm test    # юнит-тесты + Монте-Карло 10k на вероятности
npm start   # сервер на 0.0.0.0:3000 (доступен по локальной сети)
```

## `src/gameRoom.js` — стейт-машина комнаты

Один инстанс `GameRoom` держит на себе весь матч. `state` — один из
`GAME_STATES` (`LOBBY → CUSTOMIZATION → PLAYING ⇄ ROUND_RESULT → GAME_OVER`,
плюс служебный `PAUSED_DISCONNECT`, который на деле не используется как
отдельная фаза — вместо него на дисконнект отвечает таймаут, см. ниже).

Каждый обработчик `handleXxx(socket, payload)` — это реакция на одно
клиентское событие из `server.js`. После любого изменения состояния
обязательно вызывается `broadcastState()` — единственная точка правды,
которую видит клиент (`state:sync`).

### Обработчики

| Метод | Клиентское событие | Что делает |
|---|---|---|
| `handleSelectRole` | `player:select_role` | Занимает слот `player_1`/`player_2`. Оба заняты → `CUSTOMIZATION`. |
| `handleCharacterReady` | `character:submit` | Сохраняет `character` игрока, ставит `ready`. Оба `ready` → `PLAYING`. |
| `handleMakeChoice` | `game:choose_zone` | Барьерная синхронизация: ждёт зону от ОБОИХ (`strikerRole`+`keeperRole`) прежде чем звать `resolveRound()`. |
| `handleRestartGame` | `game:restart` | Голос за рестарт после `GAME_OVER` — см. ниже, отдельный раздел. |
| `handleForceReset` | `room:force_reset` | Мгновенный полный сброс в `LOBBY` (кнопка/таймаут/дисконнект — единая точка входа). |
| `handleDisconnect` | (socket `disconnect`) | Помечает игрока отключённым, шлёт `room:player_disconnected`, через 10 сек — `handleForceReset()`, если не переподключился. |

### Три вида таймеров

Все три планируются через `setTimeout`, все гасятся в `hardResetRoom()`
(вызывается из `handleForceReset()`), чтобы не оставалось "зомби"-таймеров,
стреляющих в уже сброшенную комнату.

1. **`disconnectTimer`** (`RECONNECT_TIMEOUT_MS`, 10 сек) — обрыв сокета в
   любой фазе → полный сброс, если не восстановился.
2. **`restartTimer`** (`RESTART_VOTE_TIMEOUT_MS`, 10 сек) — заводится в
   `finishGame()`. Голосование "Играть снова" (см. ниже).
3. **`idleTimer`** (`IDLE_TIMEOUT_MS`, 90 сек) — заводится/перевооружается
   `armIdleTimer()` в конце `handleSelectRole`/`handleCharacterReady`, но
   ТОЛЬКО пока комната в `LOBBY` (с хотя бы одним занятым слотом) или
   `CUSTOMIZATION`. Во время самого матча (`PLAYING`/`ROUND_RESULT`/
   `GAME_OVER`) idle-таймер не действует осознанно — нельзя обрывать игру
   из-за паузы ребёнка на подумать над зоной удара. Это выставочный
   механизм: стенд, который никто не довёл до игры, освобождается сам.

### Голосование "Играть снова" — живая правка контракта

Исходный `put_me_in_context.md` (v1.0.0) описывал `game:restart` как
мгновенный рестарт по одному клику. По требованию заказчика (выставочный
формат, оба игрока должны согласиться) это заменено на голосование:

- `finishGame()` при входе в `GAME_OVER` ставит `restartDeadline` (+10 сек)
  и запускает `restartTimer` на `handleForceReset()`.
- Каждый `handleRestartGame(socket)` помечает голос своей роли в
  `restartVotes`. Если оба `true` — таймер гасится, вызывается `_doRestart()`
  немедленно (ждать полные 10 сек не нужно).
- Если к дедлайну проголосовал только один (или никто) — `restartTimer`
  сам вызывает `handleForceReset()`: комната улетает в `LOBBY`.
- Текущее состояние голосования транслируется всем в `state:sync.restart`
  (`player_1_ready`, `player_2_ready`, `deadline` — epoch ms или `null` вне
  `GAME_OVER`) — клиент считает обратный отсчёт сам от `deadline`, без
  дополнительных тиков с сервера.

Полная формулировка живых отличий от исходного контракта —
`shared/put_me_in_context.md`, РАЗДЕЛ 7.

## `src/gameRules.js` — таблица зон и вероятностей

`resolveShot(strikerZone, keeperZone)` — чистая функция, единственное
место, где решается исход удара. Зоны 1–5:

| Зона | Позиция | Очки за гол | Промах/защита |
|---|---|---|---|
| 1, 3 | Верхние углы | 2 | 20% штанга/перекладина, 10% фартовая защита |
| 2 | Верх-центр | 2 | 20% выше ворот, 10% фартовая защита |
| 4, 5 | Нижние углы | 1 | 0% промаха, 30% защита ногой |

Если `strikerZone === keeperZone` — 100% `OBRONA_PERFEKCYJNA` (вратарь
угадал), гол невозможен. Иначе — ~70% гол независимо от зоны (проверяется
тестом на 10 000 симуляций).

## Тесты (`npm test`, `node --test`)

- `tests/gameRules.test.js` — соответствие таблице очков + Монте-Карло на
  вероятность гола.
- `tests/gameRoom.test.js` — барьерная синхронизация выбора зон, занятие
  ролей, голосование за рестарт (оба голосуют / только один → таймаут),
  idle-автосброс (срабатывает в LOBBY/CUSTOMIZATION, не срабатывает в PLAYING).

Тесты таймеров используют `t.mock.timers` (Node ≥ 20.4) — время не ждём
по-настоящему. **Если добавляете вызов, который заводит `setTimeout`
(напрямую или через `armIdleTimer`/`finishGame`), включайте мок-таймеры
ДО этого вызова** (в `beforeEach`, а не внутри `it`), иначе таймер уйдёт в
реальный `setTimeout` и будет держать процесс `node --test` живым до своего
срабатывания — весь сьют тогда искусственно виснет на секунды/минуты вместо
мгновенного прохождения.
